# 実装の説明・工夫した点

## 全体像

「TechInsight」は、1,000件（将来1万件超を想定）の技術記事を対象とした、
セマンティック検索対応のナレッジマネジメントシステムです。
`docker compose up` の一度の実行で、マイグレーション → CSV 取り込み → Embedding 生成 → Web 起動までが完了します。

### セマンティック検索の実現方式

```
記事保存時:  title + content 先頭 → "passage: " プレフィックス → e5-small → 384次元ベクトル → pgvector に保存
検索時:      自然文クエリ → "query: " プレフィックス → e5-small → HNSW インデックスでコサイン類似度上位を取得
```

- **モデル**: `intfloat/multilingual-e5-small`（多言語対応・384次元・CPU で実用速度）
  - 日本語クエリ → 英語記事のクロスリンガル検索が可能（提供CSVは英語記事のため、この性質が実用上重要）
  - API キー不要・コンテナに同梱されるため、外部サービス依存なしで動く
- **類似度**: コサイン類似度（ベクトルは正規化済み）
- **インデックス**: pgvector の HNSW。件数増加時も逐次挿入・再現率が安定

## UI/UX の観点

- **検索モードを3種類用意し、違いを UI 上で説明**
  - キーワード検索は入力中に自動絞り込み（350ms デバウンス）、セマンティック検索は Enter/ボタンで実行という使い分け。重い処理を無駄に走らせず、軽い処理は即時反映
  - モード切替時にプレースホルダとヒント文が変わり、「自然文で聞いて良い」ことが伝わる
- **関連度スコアの可視化**: セマンティック検索結果には「関連度 87%」のようなバッジを表示し、なぜこの順序なのかを利用者が納得できる
- **一覧は抜粋のみ・詳細はモーダル**: 一覧のスキャン性を保ちつつ、クリックで全文をその場で確認。一覧のスクロール位置が失われない
- **操作フィードバック**: 作成・更新・削除はトースト通知。削除は確認ダイアログを挟み誤操作を防止
- **ローディングスケルトン / 空状態 / エラー状態**をそれぞれ設計し、通信中・0件・障害時に画面が「無言」にならない
- **アクセシビリティ**: モーダルの Esc クローズ・背景スクロール固定、`role="dialog"` / `aria-label`、アイコンボタンへのラベル付与

## DB の観点

詳細は [db-design.md](db-design.md) を参照。要点:

- **1万件超を想定したインデックス設計**: HNSW（ベクトル）・pg_trgm GIN（部分一致）・B-tree（ソート/絞込）を用途別に配置し、一覧・検索とも全件スキャンを回避
- **日本語検索対応**: tsvector + 外部辞書（MeCab）ではなく言語非依存の pg_trgm を採用し、運用部品を増やさない
- **`embedding` を NULL 許容に**: 「未生成」を状態として表現でき、シードのバッチ生成・将来の非同期ジョブ化（NULL を処理キューとして扱う）につながる設計
- **一覧 API は excerpt のみ返却**: content 全文を毎回転送しない
- **シードは冪等**: 再起動時は既存件数を見てスキップ。INSERT もバッチ（500件単位）、Embedding 生成もバッチ（64件単位）で 1万件に増えても線形にスケール

## チーム開発を意識した観点

- **レイヤードアーキテクチャ**: `api（HTTP入出力）→ services（ビジネスロジック）→ repositories（DBアクセス）→ models` と責務を分離。
  例えば「検索エンジンを差し替える」変更はリポジトリ層に閉じ、「スコアの算出方法を変える」はサービス層に閉じる
- **Pydantic スキーマで API 契約を明示**: 入力バリデーション（文字数・必須）とレスポンス形状がコードとして文書化され、フロントエンドの TypeScript 型定義（`lib/types.ts`）と対応
- **Alembic によるスキーマ変更管理**: DDL を直接叩かず、レビュー可能なマイグレーションファイルとして履歴管理
- **単体テスト + Lint（ruff）+ 型チェック（tsc）+ CI**: GitHub Actions でプッシュごとに自動実行
- **設定の外部化**: 接続情報・モデル名などは環境変数（pydantic-settings）に集約。ハードコードなし
- **CSV ローダーの防御的設計**: カラム名の揺れ（日英・命名差）を自動マッピングし、解釈不能な場合は「どこに何を追加すべきか」をエラーメッセージで案内

## 保守運用・スケーラビリティの観点

- **ワンコマンド起動と自己完結性**: Embedding モデルをイメージに焼き込み、起動時の外部ダウンロードや API キー管理を不要に。オフライン環境でも動作
- **ヘルスチェックによる起動順制御**: db → backend → frontend を compose の `healthcheck` + `depends_on.condition` で制御。「DB が起きる前に API が落ちる」類の初期化競合がない
- **コネクションプール設定済み**（pool_size=10, max_overflow=20, pre_ping）
- **推論の非ブロッキング化**: Embedding 生成（CPU バウンド）は `asyncio.to_thread` でイベントループから隔離し、検索中も他のリクエストを塞がない
- **スケールパス**:
  - 記事 10 万件 → HNSW のまま対応可。Embedding 生成はジョブキューへ切り出し
  - 読み取り負荷 → API はステートレスなので水平スケール可。DB はリードレプリカ
  - モデル変更 → `EMBEDDING_MODEL` 設定と次元数の変更 + 再生成スクリプトで移行
- **フロントエンドは standalone ビルド + 非 root ユーザー実行**で本番運用を意識した軽量・安全なイメージ

## その他の観点

- **ハイブリッド検索（要件のブラッシュアップ）**: キーワードとセマンティックの結果を RRF で統合。
  固有名詞に強いキーワード検索と、言い換えに強い意味検索の弱点を相互補完
- **クロスリンガル検索**: 多言語モデルの採用により「日本語で質問 → 英語記事がヒット」が成立
- **Next.js rewrites によるプロキシ**: ブラウザは同一オリジンの `/api/backend/*` のみを叩き、
  Next サーバーが Docker ネットワーク内の backend へ転送。CORS 問題とホスト名差異をフロントコードから隠蔽
- **セキュリティ**: ORM によるパラメータ化クエリ（SQLi 対策）、React の自動エスケープ（XSS 対策）、
  コンテナ非 root 実行、依存の既知脆弱性を考慮したバージョン選定

## 既知の制約・今後の改善候補

- 認証・認可は要件外のため未実装（追加する場合は FastAPI の依存性注入で `get_current_user` を差し込む設計余地を確保済み）
- Embedding 生成が書き込みリクエストと同期（1件あたり数十ms〜）。書き込みスループットが要件になった時点で非同期ジョブ化
- 検索結果のハイライト表示、タグによる絞り込み UI は未実装（API 側のインデックスは準備済み）
